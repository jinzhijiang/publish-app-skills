> 由 2026-07-31 一次真实发版（`3.3.0+30004`）逐步实测记录，供后续发版核对与浏览器自动化参考。
> 控制台：[https://xxj.xunfei.cn/app-open-platform/#/home](https://xxj.xunfei.cn/app-open-platform/#/home)
> 项目 Skill：本 skill 的 `SKILL.md`

## 前置条件

- 已有讯飞开放平台开发者账号（账号见 `~/.config/ai-ignore-config/<项目名>/xunfei.env` 的 `XUNFEI_ACCOUNT`）
- 已构建并签名 Release APK
- 讯飞渠道包：`build/app/outputs/channels/xunfei-app-release.apk`（VasDolly 渠道名 `xunfei`）
- 无官方发版 API，全程浏览器操作

## 页面路径

| 页面 | Hash 路由 |
| --- | --- |
| 首页 | `#/home` |
| 登录 | `#/login` |
| 应用列表 | `#/app-list` |
| 应用详情 | `#/app-detail?currentApp={...}` |
| 三步上架向导 | `#/app-list/app-update` |

⚠️ `#/appManage` **不是有效路由**，直接导航会白屏。从首页点顶部导航「应用管理」进入，实际落到 `#/app-list`。

⚠️ **讯飞的状态不能走接口查，只能读页面**（2026-09-02 探查）。列表数据来自
`POST https://openapi.xunfeixxj.com/xxj-openplat/app/management/getPageInfo?c=3.0`，
**请求体是 base64 密文**（非明文 JSON），并带 569 字节的 `Authorization`、`timestamp`、
`appid: H5PC`；token 在 `localStorage.XUNFEIXXJ_APP_OPEN_PLATFORM_TOKEN`。
复现需逆向前端的加解密与签名生成，成本高且版本一变即废——**别再去找这个接口**。
其余五家无 API 平台（360、联想、阿里、百度、三星）已改为接口/HTML 解析，讯飞是唯一例外。

⚠️ 页面是 SPA，`get_page_text` 在渲染完成前只返回页脚空壳。导航后至少等 6 秒；
读到的内容里没有「普通应用 / 合作应用 / 应用认领」页签就是还没渲染完，继续等，别当成没数据。

## 操作步骤

### 步骤 1：登录

会话过期时，点顶部「应用管理」会重定向到 `#/login`。登录表单为邮箱 + 密码，凭据由发布人手动完成。

| 属性 | 值 |
| --- | --- |
| 邮箱输入 | placeholder `邮箱` |
| 密码输入 | placeholder `密码` |
| 提交 | 蓝色「登录」按钮 |
| 其它入口 | 注册 / 忘记密码 / 遇到问题 |

### 步骤 2：应用列表核对

`#/app-list` →「普通应用」页签（另有「合作应用」「应用认领」）。

表格列：应用信息 / 应用包名 / **版本状态** / 更新时间 / 操作。

- 操作列在**无审核中版本**时为「版本更新」+「查看详情」
- 有审核中版本时「版本更新」消失，只剩「查看详情」

2026-07-31 提交前：`3.1.0 已上线`，更新时间 2026-06-10 15:28:37。
提交后：`3.3.0 审核中`，更新时间 2026-07-31 14:06:49。

### 步骤 3：应用详情

点「查看详情」进入 `#/app-detail`。页面顶部为应用基本信息 + 右上角「版本更新」按钮，下方是版本历史表格。

版本历史列：版本号 / 发布类型 / 大小 / 版本状态 / 详情说明 / 操作。

| 版本状态 | 操作列 |
| --- | --- |
| 已上线 | 同版本更新、版本回退、下架 |
| 已下线 | 编辑 |
| 审核中 | （在向导页顶部提供「撤回申请」） |

历史记录：3.1.0（41.09MB，已上线）、2.1.1–2.1.10（均已下线）。线上从未发布过 3.2.x，3.1.0 → 3.3.0 跳版本属正常。

URL 参数 `currentApp` 里可见 `appDetailId`（3.1.0 为 `18757`）、`appDetailStatus`、`verifyStatus`。**不要依赖这些历史 ID 构造直达 URL。**

### 步骤 4：版本更新弹窗（创建草稿）

点右上角「版本更新」打开弹窗，标题「版本更新」。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `*应用安装包` | 上传按钮 | 提示「上传后自动解析应用名称、包名、版本号、应用权限」 |
| `*应用名称` | 只读 input | 解析回填 |
| `*应用包名` | 只读 input | 解析回填 |
| `*应用版本` | 只读 input | 解析回填，只有 versionName，无 versionCode |
| `*应用权限` | 只读 textarea | 解析回填，权限名 + 说明 |
| 提交 | 按钮 | 上传前置灰 |

文件输入选择器：`input.el-upload__input[type=file]`（Element UI el-upload，`name="file"`，无 `accept`）。

上传后文件名显示为平台存储名，例如 `ms8f1lut-0976035e892b53eadb346e08a78cb20f.apk`。

点「提交」→ 二次确认弹窗「提示 / 是否确认更新应用?」→「确认」。

⚠️ **这一步不是提审**：它创建 `<版本号> 未提交` 草稿并跳转 `#/app-list/app-update`。

### 步骤 5：三步向导

左侧栏：应用信息 / 版本信息 + 版本树（当前版本标 `未提交`，其余标 `已上架` / `已下架` / `审核中`）。
顶部步骤条：**填写应用信息 → 填写版本信息 → 提交**。
右上角按钮：暂存 / 下一步（第 2 步起变 上一步 / 提交）。

首次进入右上角有气泡提示「离开页面别忘了暂存哦~ / 我知道了」。

#### 5.1 填写应用信息

全部自动沿用上一版：

| 字段 | 限制 | 2026-07-31 取值 |
| --- | --- | --- |
| 应用名称 | — | `<应用名>` |
| 应用包名 | — | `<applicationId>` |
| 一句话简介 | 15 字 | 沿用上一版（长度贴着 15 字上限时注意计数） |
| 应用简介 | 1000 字 | 988/1000 |
| 应用分类 | 两级下拉，**只能选一个分类** | 见 `XUNFEI_CATEGORY` |
| 上传图标 | 512×512px，PNG/GIF，直角，<200KB | 已有 |
| 上传图片介绍 | 竖屏 1080×1920 或横屏 1920×1080，PNG/JPG，<1M，**3–5 张** | 5 张 |

#### 5.2 填写版本信息

15 个表单项，13 项自动沿用，**2 项必须人工处理**。

| 字段 | 必填 | 是否沿用 | 2026-07-31 取值 |
| --- | :---: | :---: | --- |
| 应用安装包 | ✅ | 上传解析 | ms8f1lut-…20f.apk |
| 应用版本 | ✅ | 上传解析 | 3.3.0 |
| 应用权限 | ✅ | 上传解析 | 252 字符 |
| **版本说明** | ✅ | ❌ **留着旧版文案** | maxlength 500，本次 284 字 |
| 隐私政策网址 | ✅ | ✅ | 已有 |
| 付费提示 | ✅ | ✅ | 含付费项目（另有「无」） |
| 付费内容 | ✅ | ✅ | 见 `XUNFEI_PAY_TYPE`；可选 会员收费 / 激活收费 / 课程收费 / 部分章节收费（图书阅读类）/ 其他 |
| 广告类型 | ✅ | ✅ | 见 `XUNFEI_AD_TYPE`；可选 无 / 轻度广告 / 重度广告 |
| 学段 | ✅ | ✅ | 见 `XUNFEI_STAGE`；可选 幼儿 / 小学 / 初中 / 高中，多选 |
| **年龄** | ✅ | ❌ **空，必须重选** | 见 `XUNFEI_AGE_RATING`；可选 3+ / 8+ / 12+ / 16+，单选 |
| 软件版权证明 | ✅ | ✅ | 《计算机软件著作权登记证书》，<2M，jpg/png |
| ICP备案网址或备案号 | ✅ | ✅ | 见 `XUNFEI_ICP` |
| 特殊类证书 | ❌ | — | 空 |
| 客服电话 | ❌ | ✅ | QQ：… |
| 备注 | ❌ | ✅ | 含测试账号（**勿复述、勿改动**） |

分区小标题：广告情况 / 应用推荐学段 / 适用年龄 / 版权信息。

**年龄档取值依据**：沿用上一个审核通过的版本所选档位（记在 `XUNFEI_AGE_RATING`）。查旧版方法：先点「暂存」（toast `暂存成功`），再点左侧版本树里的旧版本只读查看，然后点回当前版本，草稿内容仍在。

#### 5.3 提交

右上角「提交」→ 二次确认「提示 / 是否确认提交应用信息?」→「确认」。

提交成功信号：

1. 右上角 toast `提交成功`
2. 页面标题行变为 `3.3.0 提交上架  ⓘ 审核中，预计1-3个工作日反馈结果`
3. 步骤条第三步高亮为「审核中」
4. 右上角按钮变「撤回申请」
5. `#/app-list` 版本状态显示 `3.3.0 审核中`

## 自动化要点

### 上传 44MB APK

浏览器工具直传不可行（`file_upload` 限 10MB；chrome-devtools 拉起的实例无登录态），原生文件选择器不能自动化。

方案：本地起 loopback CORS HTTP 服务，让已登录的控制台页面自己 fetch 到字节，再由页面 JS 构造 `File` 注入 `input.el-upload__input` 并派发 `change`，走站点自身上传逻辑。

harness：`$SKILL_DIR/scripts/cors_upload_server.py`
完整脚本与 JS 片段见 SKILL.md 第 3 节。

### 已知坑

| 现象 | 说明 |
| --- | --- |
| 首次 fetch `127.0.0.1` 无限挂起 | Chrome Local Network Access 拦截，请求未到达服务端。查 `navigator.permissions.query({name:'local-network-access'})`，`granted` 后重试即成功 |
| CDP `Runtime.evaluate` 45s 超时 | 不要在 JS 工具里直接 `await` 大文件 fetch；用 fire-and-forget + 全局状态轮询 |
| `read_network_requests` 输出爆炸 | 此站会把 data:URI 截图整段返回；改用 `read_console_messages` 或页面内 JS |
| `find` / `read_page` 返回 empty result | 用页面内 JS 枚举 `.el-form-item` |
| 读到错误的 textarea | 第 1 步表单在第 2 步仍在 DOM 中（`v-show`），必须按 `offsetParent` 过滤 |
| 直接赋 `textarea.value` 不生效 | Element UI + Vue，需用原生 setter 再派发 `input` 事件 |
| 点击落空 | `scrollIntoView` 后坐标失效，必须重新 `getBoundingClientRect()` |

## 2026-09-01 实时补充

- 应用列表实时入口为 `#/app-list`，目标应用的“版本更新”进入 `#/app-list/app-update`；不要复用历史参数或动态请求地址。
- 实时版本历史显示已有线上版本时，先创建草稿、核对解析结果与继承字段，再进入提交步骤。
- Chrome 会话只用于页面 UI；Cookie、令牌、动态上传 URL、请求头及其他登录标识不记录、不导出，也不转换为本地 API 调用。
