## 实测入口（2026-09-01）

| 用途 | 路由 / 入口 | 实时页面信号 |
| --- | --- | --- |
| 应用列表 | `https://seller.samsungapps.com/content/common/summaryContentList.as` | 可按应用名称、内容 ID、状态筛选 |
| 审核记录 | 从应用列表的实时“未通过总测试”链接进入 | 只读详情包含应用程序信息、应用程序包、发布、数据安全及合规页签 |

当前列表同时出现销售记录与一条“未通过总测试”的草稿/审核记录。详情页未展示可读的拒审原因；在未确认“重新注册”确实复用同一应用而非创建重复记录前，不点击该操作。

> **列表状态靠列位置表达，且列由 CSS class 标识（2026-09-02）**：
> `regi` = 未提交(草稿)、**`prec` = 已提交待审（`Ready for Review`）**、`certifi` = 审核中、
> `statSale` = 销售、`date` = 上次更新时间、`tit rowTd`（纯数字）= 内容 ID、`expl` = 应用名。
> 表头占前 2 行，**一个应用跨 2 个 `<tr>`**（主行的应用信息单元格带 `rowSpan=2`，续行只有状态与日期）。
> 按 class 解析、按「遇到内容 ID 就新起一条」合并行，比按列下标稳。
> 只读查询脚本见 本 skill 的 `SKILL.md` § 0。
>
> ⚠️ **`regi` 与 `prec` 占同一列但语义相反**：`regi` = 还没交，`prec` = 已经交了。
> 2026-09-02 提交 3.5.0 后立刻踩到——解析器当时只认 `regi`，把一个刚提交成功的应用
> 读成「三列全空」。判「是否已提交」要看 `prec` 是否非空。
>
> 状态演进实测：`draft=更新中`（未提交草稿）→ 提交后 → `ready=Ready for Review`。
> **`draft` 有值不等于已提交**，这是最容易误判的地方。

## 发布与声明合同

- 新 APK 应在同一内容记录的“应用程序包”页替换，上传后核对解析版本、设备范围与可安装状态。
- 多地区分发时，英文商店资料、支持语言和截图需要完整且可读；不能把中文截图冒充英文资料。
- Google Mobile Service、AIGC、未成年人模式、美国未成年人法规和任何新协议都需要单独确认。
- 最终“提交”应在新版本记录显示 `Ready for Review` 或页面等价审核状态后复核。

## 状态与安全边界

- 仅通过 Chrome 已登录会话操作可见页面；不读取、保存或转换登录标识、Cookie、令牌、网络请求或动态上传地址。
