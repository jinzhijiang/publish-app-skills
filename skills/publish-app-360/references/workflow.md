# 360 移动开放平台 · APK 上架流程

> 由手动操作逐步记录，供后续发版核对与浏览器自动化参考。  
> 控制台：[https://dev.360.cn/](https://dev.360.cn/)
> 项目 Skill：本 skill 的 `SKILL.md`

---

## 前置条件

- 已有 360 开发者账号
- 已构建并签名 Release APK
- 360 渠道包：`build/app/outputs/channels/c360-app-release.apk`（VasDolly 渠道名 `c360`）

---

## 操作步骤

### 步骤 1：登录（未登录时）

1. 访问 [https://dev.360.cn/](https://dev.360.cn/)
2. 若右上角显示 **「登录」**，点击登录

2026-07-30 实际访问应用列表时，未登录会重定向到 `https://i.360.cn/login/`，并通过 `destUrl` 参数在登录后返回 `/mod3/mobile/applist`；登录凭据、验证码和二次验证均由发布人手动完成。

| 属性 | 值 |
| --- | --- |
| 元素 | a |
| 文本 | 登录 |
| 选择器 | `a.js-signIn` |
| 容器 | `span#statusBar` |
| href | `#nogo`（JS 触发登录，非直接跳转） |

3. 在 **360账号登录** 页面或弹窗中填写账号密码后点击 **「登录」**

| 属性 | 值 |
| --- | --- |
| 弹窗标题 | 360账号登录 |
| 账号输入 | 手机号 / 360 账号 |
| 密码输入 | 密码（掩码显示） |
| 协议勾选 | 「已仔细阅读并同意《360用户服务条款》《360用户隐私政策》」 |
| 登录按钮 | 绿色「登录」按钮 |
| 登录按钮选择器 | `input.quc-button-submit.quc-button-primary` |
| 登录按钮 value | `登录` |
| 表单容器 | `form.quc-form` / `div.quc-mod-sign-in` |
| 其他入口 | 快速注册、找回密码；QQ / 微信 / 微博 / 支付宝第三方登录 |

> **安全**：账号密码仅本地填写，勿写入文档或仓库。

**已登录状态**：右上角「登录」变为用户信息或「退出」等。

### 步骤 2：进入应用列表

登录成功后，在左侧边栏点击 **「应用列表」**。

| 属性 | 值 |
| --- | --- |
| 元素 | a |
| 文本 | 应用列表 |
| 选择器 | `a.J_menuItem` |
| href | `/mod3/mobile/applist` |
| 完整 URL | [https://dev.360.cn/mod3/mobile/applist](https://dev.360.cn/mod3/mobile/applist) |
| 侧边栏 | `ul#side-menu` / `nav.navbar-static-side` |

> **路由坑（2026-09-02）**：`https://dev.360.cn/mod/app` 返回「您访问的页面不存在」，
> 不是 404 页而是一个正常渲染的站点页面，容易误判成「登录失效」或「应用被删」。
> 应用列表只有 `/mod3/mobile/applist` 这一个有效入口。

**侧边栏菜单**（参考）：首页、**应用列表**、推广服务 …

### 步骤 4：更新应用信息

进入应用详情后，点击绿色按钮 **「更新应用信息」**（带刷新图标）。

| 属性 | 值 |
| --- | --- |
| 文本 | 更新应用信息 |
| 位置 | 应用信息区域下方，与「更新资质信息」并排 |
| 说明 | 页面提示：*更新资质信息*提交完成后，请点击*更新应用信息*提交应用审核 |

**注意**：若仅需发版更新 APK，一般点 **「更新应用信息」**；资质类材料变更才需先走「更新资质信息」。

---

### 步骤 5：上传软件安装包

进入 **「完善描述信息」** 页面，在 **「软件安装包」** 一行点击绿色 **「上传」** 按钮。

| 属性 | 值 |
| --- | --- |
| 页面标题 | 完善描述信息 |
| 按钮文本 | 上传 |
| 表单项 | 软件安装包 |
| 提示 | **请上传64位应用包**（红色） |
| 要求 | 需上传 64 位 APK，或 32/64 位兼容包 |

**本地上传文件**：

| 属性 | 值 |
| --- | --- |
| 推荐路径 | `build/app/outputs/channels/c360-app-release.apk` |
| 绝对路径 | `<项目根>/build/app/outputs/channels/c360-app-release.apk` |
| 渠道名 | `c360` |

**操作**：

1. 点击「软件安装包」旁的 **「上传」**
2. 在文件选择器中选择 **`c360-app-release.apk`**
3. 等待上传完成；页面会自动解析并显示应用信息（名称、包名、版本名、版本号等）

**2026-07-30 实际解析结果**（后续版本仍以控制台解析为准）：

| 字段 | 值 |
| --- | --- |
| 应用名称 | `<应用名>` |
| 包名 | `<applicationId>` |
| 版本名 | 3.3.0 |
| 版本号 | 30004 |

> Chrome 扩展自动上传本地文件时，需要在扩展详情中开启“允许访问文件网址”；上传后必须以控制台解析结果再次核对包名和版本。

---

### 步骤 6：填写更新说明与发布设置

上传解析成功后，保留与本次版本无关的已有分类、标签、应用简介、隐私政策、图标和截图。

| 字段 | 本次规则 |
| --- | --- |
| 当前版本介绍 | 从 `docs/发布版本更新日志.md` 复制对应版本的 Android 简体中文“商店更新说明” |
| 字符限制 | 10–400 字符 |
| 发布时间 | 默认“审核后立即发布”；若需定时发布必须另行确认 |
| 是否控量 | 默认保留已有设置；变更前必须另行确认 |
| 风险 SDK 自查 | 提交前需明确确认“已自查上传应用中无风险SDK；如检测出风险SDK将配合平台整改” |

2026-07-30 提交的 `3.3.0+30004` 更新说明共 284 字符，页面校验通过。

### 步骤 7：提交审核

2026-07-30 实测页面没有独立“保存草稿”按钮，“提交审核”会直接创建审核记录。后续若页面提供独立保存功能，可保存并重新读取验证；否则点击“提交审核”前必须单独确认：

1. APK 解析结果与本地校验一致
2. 当前版本介绍正确
3. 发布时间和控量设置正确
4. 风险 SDK 自查声明已由发布人确认

提交成功后会跳转到应用首页。成功状态的可靠信号：

- 标题显示 **“审核中”**
- 版本名称显示新版本
- 安检结果显示 **“检测中”**
- 页面出现 **“撤销审核”** 入口

2026-07-30 实际结果：目标应用 `3.3.0` 已提交，状态“审核中”，安检“检测中”。

“撤销审核”会改变已创建的审核记录，点击前必须另行确认。

## 自动化备注

- **登录**：验证码 / 2FA 需人工操作
- **APK 路径**：`<项目根>/build/app/outputs/channels/c360-app-release.apk`
- **上传控件**：旧版 WebUploader 的可见容器为 `#uploadapk_btn`；直接点击隐藏文件输入可能无法触发选择器
- **提交后状态页**：`/mod3/home/?qid=<qid>&appid=<appid>&isInCreateFlow=0`

## 2026-09-01 实时补充

- 从应用详情页的可见“更新应用信息”入口进入 `createmobile/baseinfo` 表单；入口参数由当次应用列表链接提供，不应作为固定调用接口。
- 安装包区域提示上传 64 位应用包；上传解析完成前，页面仍显示旧版本。
- 当前版本介绍限制为 10–400 字符；“风险 SDK 自查”原文是独立的合规声明，不能从已登录 Chrome 会话或 APK 上传推定同意。
- 登录会话、Cookie、令牌、动态上传地址、请求头和网络接口均不写入本仓库，也不用于本地 API 调用。
