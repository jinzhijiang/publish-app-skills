# vivo 首次上架（控制台建应用 + API 传包）

> 2026-09-04 实测记录。与 `reference.md`（版本更新）互补：本文只讲**应用还不存在**时怎么走。
> 所有路由、字段、错误码均为实调所得，未经验证的不写。

## 结论先行：API 能做的比 SKILL.md 原先写的多

原 `SKILL.md` 前置条件写着「已在 vivo 开放平台创建应用并**至少完整上架过一次**」。
**这条是错的**。实测：应用在控制台创建完成的那一刻，API 立即可用——

```
app.query.details   → 返回 mainTitle / subTitle / status / saleStatus
app.upload.apk.app  → 传包成功，返回 serialnumber
app.upload.icon     → 成功
app.upload.screenshot → 成功
```

`saleStatus=0`（未上架）不影响以上任何一个。

**真正必须在控制台做的只有两件事**：

1. **创建应用**（API 无此能力）——填包名 + 主标题 + 副标题
2. **上传版权证明**（API 无此能力，见下方 20037）

其余（传包、图标、截图、文案）都能脚本化。

## 一、创建应用

路由：`/appCreate` → 成功后跳 `/app/appService/<内部id>`

| 字段 | 约束 |
| --- | --- |
| 应用包名 | **创建后不可修改**，必须与将要上传的 APK 包名一致 |
| 主标题 | 必填 |
| 副标题 | 非必填 |

创建后页面给出三个标识，记下来：

- **App-ID**：控制台展示用
- **Cp-ID**：账号级
- **内部 id**：URL 里那个，后续 `/appPerfect/<内部id>` 要用

> 建应用**不需要**先传包，也不需要任何素材。

## 二、应用名称规范（《应用审核规范》2.2，doc/12）

发版脚本管不到这块，但填错要重新走审核，且**每年只能主动改 4 次**（2.2.9）。

| 条 | 规则 |
| --- | --- |
| 2.2.1 | 应用名称（**含副标题**）≤ **15 个汉字**或 30 个英文字符 |
| 2.2.2 | 主标题支持特殊符号；**副标题仅支持中文逗号**。主标题任意位置含 `-` `+`，或末尾含特殊符号时，**不支持副标题** |
| 2.2.3 | 不得仅由普遍、不具辨识性的词汇构成（类别词/功能词堆砌），建议含品牌辨识度内容 |
| 2.2.5 | 须与**核准名称、软著名称**一致 |
| 2.2.6 | 不得添加与主功能无关的词；**主副标题不得重复、相似** |
| 2.2.7 | **APK 内显示的应用名必须与后台填写的一致** |

实操顺序：先 `aapt2 dump badging <apk> | grep application-label` 拿到包内名称，
主标题照抄；副标题再补关键词，注意别和主标题重复。

## 三、完善信息页（`/appPerfect/<内部id>`）

右侧固定导航列出八个区，每区带完成标记（`icon-a-success` / `icon-a-error`），
用它判断还差什么最快：

```
安装包信息 / 权限信息 / 发布设置 / 展示信息 /
辅助审核信息 / 核准（备案）信息 / 资质信息 / 联系人信息
```

### 素材硬规格（页面内标注）

| 素材 | 规格 |
| --- | --- |
| 商店图标 | **正方形直角**、png、**≤500KB**、**256×256 ~ 512×512**。安装包图标合规时会自动填充 |
| 截图 | **3–5 张**、**1080×1920**、单张 ≤2MB、png/jpg |
| 介绍视频 | 可选。1920×1080 / 1080×1920 / 1280×720 / 720×1280，≤500MB，MP4 |
| 版权证明 | png/jpg/jpeg ≤5M，或 **pdf ≤10M** |

> 权限信息区有一条跨平台规则：**在 vivo、小米、OPPO、荣耀任一开放平台申请获得的权限，在各平台同步生效**。

## 四、`errno=20037` 请提供版权证明

首次上架调 `app.sync.update.app` 会被拦：

```
error: app.sync.update.app failed, subCode=20037,
       msg=请提供版权证明（APP电子版权证书或计算机软件著作权登记证书）
```

**API 没有上传资质的 method**（只有 apk / icon / screenshot 三个），
所以这一步必须在控制台「资质信息」区手工上传。

平台要求：**资质中的应用名称、公司名称需与本应用、本账号一致**，
否则要另附授权证明或补充材料。软著名带「软件」「系统」后缀而应用名没有，是常见情形。

## 四点五、控制台草稿必须填完，API 绕不过去（2026-09-04 实测）

一个容易走弯路的判断：以为 `app.upload.*` 拿到流水号后，`app.sync.update.app`
一次带齐 apk + icon + screenshot + 文案就能提审，不用碰控制台。**首次上架不行。**

- `upload` 只是把文件存到 vivo 服务端换流水号，**不会落进控制台草稿**；
  传完刷新 `/appPerfect/<id>`，安装包信息与展示信息仍是空的。
- `update` 会校验**应用级资质状态**，而资质只存在于控制台。资质区没完成时
  一律返回 `20037`，与你在 `update` 里传了什么无关。

结论：**首次上架把控制台八个区填完 → 控制台「提交审核」**；
API 留给之后的版本更新。右侧固定导航的 `icon-a-success` / `icon-a-error`
是判断"还差哪个区"最快的信号。

### 控制台表单的三个操作坑

这个后台是 element-ui + Vue，常规自动化手法有一半不管用：

| 现象 | 原因与解法 |
| --- | --- |
| radio 用 `label.click()` 或派发 MouseEvent 都选不中 | 要直接操作原生 `input[type=radio]`：`inp.checked=true` 再 `dispatchEvent(new Event('change',{bubbles:true}))` |
| select 的下拉选项点不中 | 选项渲染在 body 下的 portal 里，坐标对不上。**改用键盘**：点开后 `Down` × N + `Enter` |
| 文本框赋值后保存丢失 | Vue 不认 `el.value=x`。要用原生 setter：`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(el,v)` 再派发 `input`/`change` |

另外**「版权证明」的上传框是按需渲染的**——它前面是一个单选组
（《APP电子版权证书》/《计算机软件著作权登记证书》），不选中任何一项时
页面上根本没有对应的 `input[type=file]`（只有 4 个：apk/图标/截图/视频），
选中后才变成 5 个。而且这个上传框**只收 jpg/jpeg/png ≤5M，不收 pdf**
（区块顶部写的"或 pdf（10M以内）"是给行业资质的）。软著是 PDF 时要先转成图片。

### 资质信息区的三个必填

1. **版权证明**：先选单选项，再传图片
2. **是否授权版权证明**：不存在被其他企业授权时选"否"
3. **行业资质评估**：点"评估"打开行业类型树。金融理财下 18 个子类全是持牌业务
   （小额贷款/支付/证券/保险/征信/外汇/典当…），实用工具下 3 个
   （优化清理wifi/互联网地图/静态ip代理）也都是敏感类型。
   **这是筛查有没有踩到需牌照行业，不是给应用分类**——纯工具类应用大概率一个都不该勾。

### 年龄分级：22 题问卷

「设置」→「适龄问卷评估」，11 节共 22 道是/否题，全部必答，答完点"评估"出建议分级，
再从 3+ / 8+ / 12+ / 18+ 里选。**选了"金融理财"分类且第 22 题
（是否仅包含金融理财相关内容）答"是"，建议值会是 18+。**
系统给的只是建议，最终分级可自选，但与问卷不符时要有理由。

## 五、版本更新的长度限制（与别家不同，别共用文案）

| 字段 | 限制 |
| --- | --- |
| `updateDesc` 新版说明 | **5 ~ 200 字符** |
| `detailDesc` 应用简介 | **50 ~ 1000 字符** |
| `remark` 审核留言 | 10 ~ 200 字符 |

⚠️ **控制台与 API 的上限不一致**：更新说明在控制台表单里 `maxlength=500`，
而 API 只接受 200。控制台还有几个 API 没有的字段：
一句话简介（**17 字**）、官网链接、对外联系方式（20 字）、隐私政策 URL（300 字）。

华为的应用介绍上限 8000、OPPO 1024，vivo 只有 1000 且新版说明仅 200——
多平台发版时这三家的文案要各准备一份，不能一套走天下。

## 五点五、27MB+ 的 APK 怎么进控制台

控制台上传框走的是原生 file input，而浏览器自动化工具的直传通常有 10MB 上限
（本次实测：图标 344KB、截图 5 张合计 6.9MB 都能直传，27.9MB 的 APK 不行）。

用 `chrome-file-upload-bridge`：本地起 CORS 静态服务，页面自己 fetch 到字节，
再用 `DataTransfer` 塞进 input。**关键坑**——Chrome 的 Private Network Access
会**静默挂起**第一个 HTTPS 页面发往 `127.0.0.1` 的请求：

- 不报错、不 reject，`fetch` 的 promise 永远 pending
- **服务端日志里完全没有这条请求**，看起来像什么都没发生
- 需要用户在 Chrome 里点一次"允许"，之后同源请求都通

所以流程是：起服务 → 页面发一个 HEAD 探活 → **等用户点允许** →
确认服务端日志出现请求 → 再注入大文件。别一上来就传 APK，否则分不清是
没放行还是传失败。

注入后 `input.files.length` 立刻读到 0 是正常的（element-ui 在 change 里
接管后会清空），以**页面回显的文件名**和右侧导航的完成标记为准。
